# 短剧审查

优先由未参与当前版本创作的 reviewer 执行；条件不允许时可以自检并如实说明。本技能定位问题、影响和
必须达到的修订结果，将修改交回负责技能；审查与修改分开执行。

## Quick Start

直接读取用户点名的当前文件。单集审查需要落盘时写 `审查/EP001-审查.md`；独立文件审查使用
`审查/<主题>-审查.md`。用户只要口头结论时直接回复，不为“完整”创建审查文件。

审查 Markdown 建议结构：

```markdown
# EP001 审查

- 范围：剧本、分镜、视频提示词
- 结论：REVISE
- 复核方式：独立 reviewer / 自检

## Blocker · REV-001 · 画面文字未被镜头承载
- 位置：剧本.md / EP001-SC002；分镜.md / SHOT-EP001-004
- 证据：……
- 影响：……
- 修订结果：由 short-drama-storyboard 补入准确文字及可读条件。
- 规则：SHT-01 · structural_invariant
```

引用只使用文件名、标题 ID、行号或短引文；不建立 sources 声明、哈希、record ID 或第二套状态。

## 工作流

### 1. 确定范围

写清当前要审哪些文件、章节、镜头或提示词，以及创作者已经明确的限制。目标在审查中发生变化时，
重新读取再下结论。

### 2. 先查可证明事实

- 五文档的可见 ID、引用和时长是否一致；
- 剧本对白、动作、声音、画面文字是否都有画面/声音承载；
- 人物、地点、道具状态和镜头起止是否连续；
- 提示词是否从准确起点到准确终点；
- 目标模型画音同轨时，声音内容、时序和发声边界是否与来源一致；无对白镜是否交代底声或静默
  （`VID-22`、`VID-23`，见 [视觉运动审查表](references/rubric-visual-motion.md)）；
- 打斗、追赶、群戏镜的动作是否写足速度承担者与并行标记（短促动词、`as / while /
  at the same time` 挂载、双人接触错开 0.3–0.5s、终点留惯性），而不是被减速修饰包住或
  写成会被按顺序渲染的并列结构（见 [视觉运动审查表 · 动作速度与同时性](references/rubric-visual-motion.md#action-speed-and-simultaneity-fights-chases-group-scenes)）；
- 剧本末尾「## 声音分层」（如存在）与分镜、剪辑单的口型处理是否一致；跨场缝是否两侧都有
  「转场交出 / 转场接住」且手法已选；承担本集主要戏剧功能的支点场是否只有单线单回合结构；
- 剪辑单各缝是否有与分镜转场对应的 `- 转场：` 行（手法一致、帧数已落），使用后期配音或声音模仿时
  是否有音色登记且同角色一致；视频提示词的登记行是否不与 `### 可复制提示词` 正文同格式相邻；
  分镜母题行是否首次出现与承接成对、剧本已写的人物反应是否投影进镜头、每场是否较场首有可见变化；
  音色只核**集内**一致；跨集身份以 `视觉设定.md` 的 `voice_direction`（`AST-07`）为准，剪辑单
  登记与它冲突时报资产负责人，不认剪辑单为新权威；
  母题物件的识别特征是否与 `视觉设定.md` 的道具条目逐字一致（资产是唯一登记处，分镜行是引用）；
- 私有输入、凭据、绝对路径或内部流程文字是否泄漏。
<!-- mount:wuxia-fight v1 begin -->
- 武打镜（含 `- 武打：` 登记或明显是攻防）：接触点是否在攻守两侧同一位置同一本体角度、去掉招式名
  后四问是否答得出（谁用什么攻/对方如何格挡/在哪接触/双方之后怎么弹开）、命中是否在**命中后的镜里**
  留一项可见后果、场内连续三镜同相位、单一景别是否占掉全集武打镜的八成；判据与豁免口径见
  [武打动作审查表](references/rubric-fight-action.md)。缺失只报证据并路由分镜与资产负责人，不代改。
<!-- mount:wuxia-fight v1 end -->

缺少必要输入时只停止依赖它的判断，其他问题可以继续汇总。

母题、表情投影与场级推进这三项，判错时只认下列形态，不凭“感觉不够”：

- **母题**：分镜写了某物/某声/某动作，但只有首次出现、后文无承接；或后文有承接、前文
  从未登记其最初含义。两种情况都 cite 两处镜号；只出现一次且不承担对照功能的物件不算母题，
  不报。
- **表情投影**：剧本在该镜写了人物反应（态度反转、谎言被戳、话被打断），而镜头起点、动作、
  终点三处没有任何一处承载该反应；只有分镜自己新发明、剧本没有的反应不报缺陷，记为 `note`。
- **场级推进**：同场首尾对比，人物状态、空间关系、信息占有任何一项都没有可见变化；无变化
  但已在分镜末端点名为过场的，不报。

### 3. 带证据审内容

每个 finding 包含位置、必要短引文或冲突事实、观众/制作影响、必须达到的修订结果、负责技能、严重
程度、规则等级和 `open` / `closed` 状态。“AI 味”“不够电影感”或无证据分数不能替代这些内容。

### 4. 跨文档综合

```text
剧本事实 -> 视觉设定 -> 镜头职责与边界 -> 冻结关键帧 -> 视频运动 -> 下一状态
```

优先守住原意、知情时机与连续性，不奖励脱离来源的华丽提示词。

### 5. 结论与分派

- `APPROVE`：没有阻断问题；
- `APPROVE_WITH_NOTES`：只有不阻断的改进；
- `REVISE`：存在阻断交付的结构缺陷、经证据确认的内容缺陷或已接受限制冲突；
- `PROVISIONAL`：关键输入不足，暂时无法完成判断。

按负责技能分组修订要求。本轮完成后交还控制权；修改和复审只有用户明确请求时开始。

## 投产前闸门（生成前）

> `craft_default`。本节只查可证明事实，不评创作、不替代上面五步；它的作用是把"必然会出问题"的
> 事实提前到花钱之前。整集要送生成时逐项核对，结论落盘。

1. **续接路由是否真的开着**：执行端有连续性开关时核对 timeline 的 `output.continuityEnabled`；
   已经跑过一段的，抽查产物同名 `.meta.json` 的 `continuity` 与 `continuity_from_prev`。
   分镜里存在连拍回合而整集全为 `false`，记 `blocker`——成片会在每个剪辑点重新起势。
2. **每张有脸的画面是否都有身份来源**：逐镜比对人物与 `身份` / `造型状态` 参考的覆盖，
   列出"检出人脸却没有参考、也没有换脸结果"的镜头。有台词或有正脸近景的配角与主角同一标准。
3. **起始帧是否被裁切**：宽画幅由更高画幅裁切得到时，核对裁切结果有没有切到头顶、下颌或持械手；
   标了 `clipped` 的镜回 `$short-drama-image-prompts` 重出，不带着切脸帧进生成。
4. **画幅、档位与画面条件是否相容**：低步数加速档 + 暗场夜雨 + 快速横摇/横移不要整集叠加；
   成片重新编码的码率明显低于单段产物时记 `major`，模糊会在这一步被放大一次。
5. **闸门结论落盘**：`审查/` 为空时不能声称"审过了"；结论写进审查文档，注明核对的是哪一版产物。

## 严重程度

- `blocker`：不安全、不可交付或会让流程走错；
- `major`：明显破坏剧情理解、连续性或制作结果；
- `minor`：有具体影响但不阻断；
- `note`：创作选择或可选润色。

## 边界

- 不提交图片、视频、TTS 或音乐任务，不配置 adapter，不把 Dashboard 操作当生产授权。
- 无法读取媒体时明确限制，不从文字或 adapter 状态推断脸部一致、表演、口型、混音或市场表现。
- 生产观察必须绑定准确输入、提示词、参考、配置和结果版本；不能泛化成通用规则。
- 审查文件只保留修订所需的最小证据，不复制完整私有输入。
