# 音轨可渲染性：镜型判定与拆镜

分镜默认按戏剧需要设计镜头。目标模型是**单轨生成**（一镜一条音轨、一段连续发声）时，镜头还要多过一道门：  
**这个镜头里的声音，执行端到底发得出来吗**。本文件只回答这一件事，不改镜头职责与时长设计。

只在目标档案声明 `target_video_model` 属于单轨音频模型（如 `minimax-h3`）时打开。

## 一、三个镜型标记

分镜时给每个**有声音**的镜头标一个类型，写在本镜字段里：

```markdown
- 镜型：SOLO
```

| 标记     | 画面形态                    | 音轨          | 允许的台词                 |
| ------ | ----------------------- | ----------- | --------------------- |
| `SOLO` | 单人，面向镜头或过肩侧脸说话          | 一条，该说话人音色   | ✅ 该角色台词（一句一镜最稳）       |
| `OTS`  | 过肩/正反打，画面里两人但只有**一人**发声 | 一条，发声者音色    | ✅ 只有发声者的台词；不说话者背面或出画  |
| `DUO`  | 双人同框，两人都说话              | 一条，无法分派两条音色 | ❌ **不得有台词**；只做反应镜/环境声 |

无对白的镜头不必标（或标 `—`）。

**机械门**：`DUO` + 台词 = 错误。检查方式很简单——只要一个镜头里出现两句以上、且说话人不同，  
它就不是 `SOLO`/`OTS`，必须拆。

## 二、为什么 DUO 一定失败

生成端一镜只解出一条音轨、一个音色来源。当同一镜头要装两个说话人：

- 口型会落在画面里**最显眼的那张正脸**上，不一定是说话的人（这是已有实测结论，19 条样本一致）；
- 第二条音色无处挂——挂两条参考音频时，模型只取其中一条，或两条都不取、退回念提示词描述；
- 结果就是「有语音但内容对不上」或「干脆没有语音」。**这不是 prompt 能修的，是执行端形态。**

所以 `DUO` 只在两种情况下允许存在：**没人说话**（纯对峙、纯打斗），或台词改走画外音。

## 三、把 DUO 拆成 SOLO/OTS 的四种手法

| 手法        | 做法                                            | 适用          |
| --------- | --------------------------------------------- | ----------- |
| **正反打**   | A 说话 → `SOLO` A；切 B 的反应 → 无台词；B 回话 → `SOLO` B | 对峙、谈判、问答    |
| **过肩**    | 镜头在 A 肩后，画面里 B 正面说话 → `OTS`；A 只有背影            | 审讯、逼问、壁咚    |
| **画外音**   | 保留双人同框画面，说话人放在画外（或背身），台词记 `[VO]`/`[OS]`       | 打斗中喊招、旁观者插话 |
| **动作位隔断** | 一句一人，中间插 0.5 秒反应镜（无台词），台词分给两次生成               | 双人打斗中的文戏回合  |

优先级：正反打 > 过肩 > 画外音 > 动作位隔断。前两种才能保住对口型。

## 四、打斗镜的专属规则

打斗段落天然是 `DUO`（两人同框），因此：

1. **同框的回合只能有一个发声者**：出招方喊招名，接招方闭嘴（背影、侧脸或不在画面）。
2. **两个人不能各喊一招**：那不是两镜，是一个镜头的违规写法。要交替喊招，必须拆正反打。
3. **喊招是短句**：2~4 字（「崩云」「荡剑式」「断流」）。整句解释留给文戏镜。
4. 混战（三人以上）默认全部走 `DUO` 无台词 + 画外喊招，不要试图让画面里的人开口。

## 五、时长必须是「合法帧数」

本机导演台（ComfyUI 直连）按帧出片，采样帧数会被**向上**对齐到 `17k + 5` 网格  
（5, 22, 39, 56, 73, 90, 107, 124, 141, 158, 175, 192, 209, 226…）。  
分镜写自然秒数（如 5.5s、6s）时，执行端先按 `round(秒×帧率)` 取整、再向上补齐。

### 5.1 导出帧数的真公式（不是「取整偏差」，是固定加 12 帧）

连续链开启时（`continuityEnabled` 默认开，`continuityOverlapFrames` 默认 22），执行端为每段  
额外采样 `ctx` 帧前文语境、导出时再切掉，实际落盘长度是：

```
export_frames = align17k5(length + ctx) − ctx
```

`align17k5` 是向上对齐到 `17k+5`。于是：

| `length` 取模                      | `length + 22` | 对齐后 | `export_frames`   | 结果        |
| -------------------------------- | ------------- | --- | ----------------- | --------- |
| `≡ 0 (mod 17)`，如 102 / 119 / 204 | 已是 `17k+5`    | 不变  | **= length**      | **零漂移**   |
| `≡ 5 (mod 17)`，如 124 / 192 / 209 | 差 12 帧        | +12 | **= length + 12** | 每段 +0.5 秒 |

**首段例外**：段 0 没有前文语境，`ctx = 0`，导出恒等于 `length`。

实测印证（EP001，36 段，全部 `length ≡ 5`，设计 4770 帧 / 198.75 秒）：

| 量             | 值                                       |
| ------------- | --------------------------------------- |
| 公式预测          | 5190 帧 / 216.25 秒                       |
| 逐段数视频帧实得      | **5177 帧 / 215.71 秒**（比预测少 13 帧）        |
| 容器 `Duration` | 216.29 秒（比帧数折合多 0.58 秒，是 36 段 AAC 编码延迟） |

段 1 实测 204（192+12）、段 2 实测 102（90+12）、段 32 实测 221（209+12），公式逐段命中。  
少的那 13 帧是这样来的：**13 段各少 1 帧**，且全部是预测值 `≡ 1 (mod 3)` 的段  
（124→123、136→135、187→186），属编码器末帧处理，不是我算错，也不是丢内容。

所以验收口径：逐段与实际比，**±1 帧算编码舍入**（全片累计 0.54 秒，不影响观感），**≥2 帧才算丢帧**。  
**不要用容器时长判**——它含 AAC padding，天然比帧数多出 `段数 × 约 16 ms`。

### 5.2 所以「时长」字段该填哪个网格

**要零漂移，`length` 必须取 17 的整数倍**（不是 `17k+5`）：

| 导出帧数（= `length`） | 102  | 119  | 136  | 153  | 170  | 187  | 204  | 221  |
| ---------------- | ---- | ---- | ---- | ---- | ---- | ---- | ---- | ---- |
| 秒 @24fps         | 4.25 | 4.96 | 5.67 | 6.38 | 7.08 | 7.79 | 8.50 | 9.21 |

需要 6 秒就写 6.38（153 帧）或 5.67（136 帧），不要写 6.00。  
批量写 `segment.length` 时 `durationSec = length / 帧率`。

`ctx` 改了要重算：要 `length + ctx ≡ 5 (mod 17)`，即 `length ≡ (5 − ctx) mod 17`。  
`ctx = 22` 时得 `length ≡ 0`；`ctx = 0` 时得 `length ≡ 5`（这时才是 `17k+5` 网格）。

目标档案声明了别的帧率或别的量化规则时按该档案换算，并在《分镜.md》开头写一行本集采用的帧长口径  
与 `ctx` 值。

**对白容量校核**：一句 12 字按约 4~~5 字/秒需 2.5~~3 秒发声窗口；最短可用档 4.25 秒只放一句，  
且要留出开口前与说完后的反应时间。装不下就拆，不压缩语速。  
连续链会给每段尾端多加 0.5 秒（见 5.1），别把这半秒算进发声预算——它落在台词之后，通常是静音或残响。

## 六、参考图配比：每镜挂几张

参考图决定「这个人还是不是这个人」。只挂起始帧，人物一致性全靠第一帧；起始帧本身是生成的，  
误差会沿整段放大。本机执行端每段最多挂 9 张，实际建议固定 2~3 张：

| 槽位    | 挂什么            | 作用        | 备注               |
| ----- | -------------- | --------- | ---------------- |
| 1     | 本镜起始帧          | 定构图、姿态、光线 | 必须存在，缺了就是 `无锚点镜` |
| 2     | 主角三视图/T-pose 板 | 定脸型、发式、体型 | 该镜主角是谁就挂谁        |
| 3（可选） | 场景板            | 定空间与陈设    | 只在场景首次出现或切场时挂    |

槽位号只是给人看的挂图顺序；写进 `refs` 时按数组顺序（0-based）排，**不放 `index` 字段**——  
和参考音频同一个坑，写 1/2 会落空槽。

**硬规则**：

- **缺起始帧的镜头不得用资产板顶替**。`IMG-xxx` 那种多格排版板喂给参考生视频，  
  有概率把「多格」照抄进画面，出来是分屏。缺图就补图，或明确标 `无锚点镜` 并接受一致性下降。
- **同一角色同一外观串逐段一致**。发式/衣色/佩饰的描述不要每镜手写，从一张「角色锚点表」取：

```markdown
| 角色 | 锚点串（逐字复制，不改写） |
|---|---|
| 令狐冲 | 青灰布衫、袖口磨白、高马尾、左眉一道浅疤 |
| 向问天 | 玄色长袍、银线云纹、半束发、右手虎口旧伤 |
```

- 三视图与起始帧若来自不同批次，先核一次脸，不一致就重出起始帧，不要指望参考图去拉。

## 七、镜头表要补的几列

分镜表默认是给人读的。要交给脚本执行，还缺四列：

| 列               | 取值                       | 为什么必须有                          |
| --------------- | ------------------------ | ------------------------------- |
| `export_frames` | 17 的整数倍（见 5.2）           | **写帧不写秒**。秒是推导量，写秒必然二次换算出错      |
| `音色`            | 该镜挂的 wav 文件名，无台词留 `—`    | 绑定关系不能只存在《视觉设定.md》，改一句台词要回三层找归属 |
| `验收基线`          | `预期台词 / 最短发声秒 / 允许最长静音秒` | 验收时没有基线就只能「凭感觉能不能听清」            |
| `refs`          | 该镜挂哪几张图（按槽位顺序写文件名）       | 缺图、错图、少挂三视图都能被脚本查出来             |

`验收基线` 写法：

```text
- 验收基线：台词「前辈这刀，是扶桑的形制。」/ 最短 2.5s / 最长静音 1.2s
```

同时把整张分镜表导出 `分镜.csv`（UTF-8，一镜一行）供脚本消费。  
用正则从 markdown 抠字段的做法，格式一改就全空——本轮 36 段就是这样抠出来的，字段名一变整轮重算。

- [ ] 没有任何 `DUO` 镜头带台词
- [ ] 同一镜头的台词属于同一个说话人
- [ ] 每镜 `export_frames` 落在合法帧数网格内，且 `Σ export_frames` 已按 5.1 反算成片帧数
- [ ] 打斗镜一回合只有一人喊招
- [ ] 一句 ≥12 字的台词，要么单独成镜，要么已按语义断点拆开
- [ ] 每镜 `refs` 至少含起始帧；缺图处没有用资产板顶替
- [ ] 同一角色的外观描述与本集锚点表逐字一致
